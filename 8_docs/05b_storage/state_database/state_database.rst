Overview and Subsystem Mandate
==============================

The ``5_storage/state_database/`` repository constitutes the centralized persistence vault for
recursive Bayesian state estimation in the **AETHER-MRID1607X** earth observation platform.
Formulated in Stage 06 (``1_notebooks_sandbox/06-state-estimation-engine.ipynb``), this subsystem
archives prior/posterior ensembles, empirical error covariances, Kalman Gain matrices, and dynamic
trajectory rollouts generated by the **Stochastic Ensemble Kalman Filter (EnKF)**.

Primary objectives:

1. **Dynamic Soil Parameter Tracking:** Recursively update root-zone moisture and coupled soil hydraulic
   parameters (:math:`\rho_b, K_{\text{sat}}, \text{SOC}`) using spaceborne and in-situ observations.
2. **Uncertainty Variance Contraction:** Compress forecast uncertainty via Bayesian conditioning,
   suppressing error propagation into downstream agronomy and civil translators.
3. **Cryptographic Provenance:** Bind the assimilation state database to immutable SHA-256 signatures
   verified during master system release audits.

Observation Operator & Kalman Gain
----------------------------------

With observation operator :math:`\mathbf{H} = [1, 0, 0, 0]` and observation noise variance :math:`R = 0.0004`:

.. math::

   \mathbf{K} = \mathbf{P}_f \mathbf{H}^T \left( \mathbf{H} \mathbf{P}_f \mathbf{H}^T + R \right)^{-1} = \begin{bmatrix} +0.600739 \\ -0.484921 \\ +2.056300 \\ +0.527192 \end{bmatrix}

Brutally Honest Disclosures & Caveats
=====================================

1. **Unobserved Parameter Cross-Covariance Vulnerability:**
   Parameters :math:`\rho_b, K_{\text{sat}}, \text{SOC}` are updated solely through sample covariances
   in :math:`\mathbf{P}_f`. Finite ensemble sampling errors (:math:`N=50`) can introduce spurious updates.
2. **Linear Update on Non-Linear Vadose Physics:**
   Large observation innovations can theoretically push posterior ensemble members outside admissible
   retention limits. Explicit projection clamps (:math:`\theta \in [\theta_r, \theta_s]`) are enforced.
3. **Filesystem Duplication Hazard:**
   ``enkf_state_database.pt`` is duplicated across ``5_storage/notebook_results/`` and ``data/processed/``.
   Production workflows must bind strictly to ``5_storage/state_database/``.
4. **PyTorch 2.6 WeightsUnpickler Compatibility:**
   The archive embeds NumPy array structures; deserialization must supply ``weights_only=False``.
